## What this is

Open Coffee is a shared way to write down facts about coffee: which cafés exist, where they are, when they open, what they brew, whether they roast their own beans. It also describes coffee equipment models and brew methods. The standard is a set of [JSON Schema](https://json-schema.org/) files (draft 2020-12) that any program can use to check a data file, a JSON-LD context that maps coffee places to schema.org's `CafeOrCoffeeShop`, and the [Schema Explorer](https://schema.roastbook.coffee/), which explains every field of every version without jargon.

The data itself lives in [Roastbook/open-coffee-data](https://github.com/Roastbook/open-coffee-data). Browse every schema version, field by field, in the [Schema Explorer](https://schema.roastbook.coffee/), or paste a record into its [Playground](https://schema.roastbook.coffee/playground/) to check it.

## Quick start

Every schema is served at its `$id`. Download the coffee places schema and the shared definitions it references, then validate a city file with [ajv-cli](https://github.com/ajv-validator/ajv-cli):

```sh
curl -sSO https://schema.roastbook.coffee/coffee-places/coffee-places.schema.v0.1.0.json
curl -sSO https://schema.roastbook.coffee/common/common.schema.v0.1.0.json
curl -sSO https://data.roastbook.coffee/datasets/coffee-places/de/munich.json

npx -y -p ajv-cli@5 -p ajv-formats@3 ajv validate --spec=draft2020 --strict=true -c ajv-formats \
  -s coffee-places.schema.v0.1.0.json -r common.schema.v0.1.0.json -d munich.json
```

A minimal valid file with one place looks like this ([more examples](examples/)):

```json
{
  "$schema": "https://schema.roastbook.coffee/coffee-places/coffee-places.schema.v0.1.0.json",
  "meta": { "version": "2026.11.05.1", "generated_at": "2026-11-05T12:00:00Z", "country_code": "DE", "city": "example-city" },
  "places": [
    {
      "id": "cp-7k2m9x4qvd",
      "name": "Corner Café",
      "status": "unverified",
      "checked_at": "2026-11-05T12:00:00Z",
      "address": { "country_code": "DE" },
      "location": { "lat": 48.14, "lon": 11.58 },
      "specialty_tier": "unknown"
    }
  ]
}
```

TypeScript users can install the generated types, the schema files and the enum values as [`@roastbook/open-coffee-schema`](packages/schema/README.md) from the GitHub npm registry.

## Repository structure

| Path | Contents |
|---|---|
| `schemas/<family>/<family>.schema.vX.Y.Z.json` | The schemas. The repository path minus `schemas/` is the URL path of the `$id`. Published files are never edited. |
| `schemas/coffee-places/coffee-places.context.vX.Y.Z.jsonld` | JSON-LD context mapping places to schema.org `CafeOrCoffeeShop`. |
| `examples/<family>/{valid,invalid}/` | Files that must pass and must fail validation. CI checks both. |
| `docs/` | [governance](docs/GOVERNANCE.md), [decisions](docs/decisions/), [runbook](docs/runbook.md). |
| `site/` | The Schema Explorer (Astro): property trees, diffs, playground. |
| `packages/ui/` | `@roastbook/open-coffee-ui`, the header, footer and tokens shared with the Data Explorer. |
| `packages/schema/` | Source of the `@roastbook/open-coffee-schema` package (types, schemas, enum values). |
| `lib/`, `scripts/` | The schema walker shared by checks, docs and site; `validate.sh`, `build.sh`, `release-assets.sh`. |

`scripts/validate.sh` runs every check CI runs and `scripts/build.sh` builds the site into `dist/`. Both need [Bun](https://bun.sh) (`.bun-version`).

## Versioning and stability

- Schemas use [semantic versioning](https://semver.org/). Each version is its own file and its own URL, so a data file that names a version keeps validating forever.
- A published schema file is never changed. CI compares every file under `schemas/` with every `v*` tag and fails on any difference.
- New optional fields need a minor version. Removing a field, adding a required one, narrowing a type, enum, pattern or range, or closing an object needs a major version. CI computes the difference between versions and fails when the bump is too small. While the standard is a pre-release (0.x), everything shifts down one place: a breaking change needs a minor bump (0.1 → 0.2) and an addition a patch bump; 1.0.0 marks the first stable release.
- Major versions are announced in Discussions at least two weeks before release ([governance](docs/GOVERNANCE.md)).
- `https://schema.roastbook.coffee/<family>/<family>.schema.latest.json` always points at the newest version. Use it for exploring, not for validating data you publish.

## Contributing

Proposals are welcome: open an [issue](https://github.com/Roastbook/open-coffee-schema/issues/new) first, then a pull request. Read [CONTRIBUTING.md](CONTRIBUTING.md); every commit needs a DCO sign-off (`git commit -s`).

Café owners do not need this repository: claim or correct your place in [open-coffee-data](https://github.com/Roastbook/open-coffee-data/issues/new) with an issue opened from an address on your website's domain or linked from your website or Instagram bio.

## Sources and licensing

- Everything in this repository (schemas, code, site, docs, examples) is [MIT](LICENSE).
- The standard is designed for redistributable data. Ratings from other services are stored as links only, and no Google Maps or OpenStreetMap data is used (a Google `place_id` may be stored as a cross-reference, nothing else).
